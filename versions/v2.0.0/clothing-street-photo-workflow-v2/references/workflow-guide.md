## 路线分工：底图选择与生成的关键区别

本版本明确划分两条可选路线，核心差异体现在**底图准备阶段**与**工具调用组合**：

### 路线 A：通用图片参考路线（已有底图挑选）
- **核心逻辑**：面向已有实拍照片、过往生成图或第三方街拍图库的场景。
- **底图操作**：**严格“只选图不生成”**。从现有图库中挑选单张构图、动作、现场光线合适且衣服结构未被严重遮挡的图片，裁切为单张送去换装。
- **提示词对应**：直接使用 [step-prompts.md](step-prompts.md) 中的第 4 步。

### 路线 B：原教程复现路线（无底图时候选生成与质检）
- **核心逻辑**：面向无现成合适底图、需通过生图工具自行准备街拍场景的场景。
- **底图操作**：
  1. **候选生成**：使用 Higgsfield / Soul 2.0 结合已锁定的角色参考（如 Soul ID）生成街拍候选底图池；
  2. **三重质检**：人工严格筛查候选图——① 是否保持同人特征；② 服装展示区域是否清晰可读（无大面积不合理遮挡）；③ 姿势动作与现场光线是否自然；
  3. **选定单张**：选出 1 张最佳候选作为换装底图。
  4. **跳过条件**：若已有满意实拍图或合格底图，同样直接跳过生成环节。
- **提示词对应**：详细平台对照与街拍底图生成提示词见 [tutorial-platforms.md](tutorial-platforms.md)。

## 三类主要图片的职责

- **人物主图和表情图**：提供身份、外观及需要的视角，不把参考里的背景一并搬过去。
- **拍摄底图**：提供姿势、构图、机位与现场光线，不以底图原人物决定目标长相。
- **商品图**：提供实际款式、颜色、版型与细节，不继承商品照片里其他模特的身份。

摄影参考是可选补充。把主光方向、明暗和落影说清楚即可，描述越长不一定越有效。CCD直闪、自然光、逆光等按本次需求选择，不同时堆叠互相矛盾的布光。

## 人物名称不是图像输入

可以把选定的主图和表情图称作“人物1”，但这个名称只是方便交流。生成工具仍需要收到或访问对应的图像依据。

- **有角色库**：使用工具实际支持的角色引用（如原教程 Soul ID），可以减少重复上传。但必须基于真实存在的能力，用户指定的角色未建好时标注为待完成，先准备提示词并完成真实角色核验；仅在用户接受替代时改用普通图片参考，不把它称为 Soul ID。
- **没有角色库**：直接用图片集合作为参考，也能完整顺畅地继续流程。
- **同一对话已能引用图片**：沿用现有引用；无法访问时再补图。

确认图片清楚、长相一致，并按本次视角选用必要参考，不要求每次把所有表情图都塞进去。

---

## 按实际能力调整输入

不同工具接受的图片数量、引用语法和编辑方式不同。提交前按实际输入重新标图号和用途，不把另一平台的角色ID、按钮名或引用格式照搬过来。

可以联合编辑时，将底图、人物和商品参考一起组织清楚。若工具只能处理部分输入，说明能够完成的范围，再决定是否分步处理或使用其他受支持的方式；不要把缺少角色库误当成不能使用参考图片。

## 服装替换与品控

单件上衣只换上衣，单件下装只换下装，连衣裙按其覆盖范围替换，两件套分别对应上装和下装。未要求变化的其他衣物、鞋与配饰保留，材质和设计以商品图可见内容为准。

结果对照人物和商品原图查看，尤其注意款式、颜色、文字字体、遮挡和光影。局部修整后也检查其他区域是否被改动。效果以实际结果为准，不承诺一次完成或完全免修。

## 原教程与可选环境说明

原作者教学视频（普渡众神花，《AI街拍图落地skill》，作品ID：7678281289945861376）展示了基于特定平台的落地流程：
- 使用 Higgsfield / Soul 2.0 挑选模特候选并生成街拍候选底图；
- 使用 GPT ImageGen（图像生成功能）进行同人表情与正侧角度扩展；
- 使用 Codex 串联实际可用的图像编辑工具执行换装替换；
- 高要求项目的复杂印花、文字与细节边缘漂移，作者建议必要时进入 Photoshop 进行精修。

以上是原教程的特定实现案例，本 Skill 提取其核心方法并提供通用化与规范化封装。在其他生图与编辑工具中，在实际支持的范围内适配相同的素材分工与提示词结构，结果仍须逐图核验，不能保证跨模型获得相同效果。
